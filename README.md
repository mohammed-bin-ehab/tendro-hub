# TENDRO — موقع توثيق المشروع (النسخة 0.1)

## التشغيل
1. Node.js إصدار 20 أو أحدث، وقاعدة PostgreSQL (مثلاً Neon المجانية).
2. انسخ `.env.example` إلى `.env` وضع `DATABASE_URL`.
3. `npm install` ثم `npm start` وافتح http://localhost:3000
4. `npm test` يشغّل الاختبارات على PostgreSQL مؤقتة داخل الذاكرة (لا تحتاج قاعدة حقيقية).

عند أول تشغيل على قاعدة فارغة تُنشأ الجداول والأقسام وكلمات سر مؤقتة عشوائية للأربعة في `data/initial-passwords.txt`.
على استضافة بقرص مؤقت (Render) فعّل `LOG_INITIAL_PASSWORDS=1` لمرة واحدة لتقرأها من سجلات النشر، ثم احذف المتغير.

## نقل بيانات SQLite القديمة إلى PostgreSQL (مرة واحدة)
```
DATABASE_URL="postgresql://..." node --disable-warning=ExperimentalWarning scripts/migrate-sqlite-to-pg.js path/to/tendro.db
```
يتطلب Node 22.13+ لقراءة ملف SQLite. يرفض العمل إذا كانت القاعدة الهدف تحوي مستخدمين، ولا يعدّل ملف SQLite. كلمات السر القديمة تبقى كما هي.

## متغيرات البيئة
- `PORT` المنفذ (الافتراضي 3000)
- `DATABASE_URL` رابط PostgreSQL (مطلوب)، مثل `postgresql://user:pass@host/db?sslmode=require`
- `PG_POOL_MAX` أقصى عدد اتصالات (الافتراضي 5)
- `LOG_INITIAL_PASSWORDS=1` يطبع كلمات السر الأولية في السجل عند أول تشغيل فقط
- `COOKIE_SECURE=1` فعّله عند النشر خلف HTTPS
- `ADMIN_USERNAME` اسم المستخدم الذي يحصل على دور المدير عند بدء التشغيل (الافتراضي `mohammed`). بعد تسجيل الدخول تظهر له «لوحة الإدارة» لإضافة الأعضاء، وتغيير أدوارهم وحالة حسابهم وكلمات مرورهم، وإدارة الأقسام والصلاحيات والألوان.
- `GOOGLE_TRANSLATE_API_KEY` مفتاح Cloud Translation. انسخ `.env.example` إلى `.env` وأضف المفتاح؛ لا تضعه في ملفات الواجهة أو تشاركه. عند غياب المفتاح يُحفظ النص الأصلي وتظهر حالة أن الترجمة معلّقة.

عند الحفظ، يكتشف الخادم العربية أو الإنجليزية من النص، ويرسل النص إلى Google Cloud Translation لإنشاء النسخة المقابلة. تُخزّن النسختان في PostgreSQL ويُعرض النص الموافق للغة المختارة. تُترجم النصوص القديمة عند فتح القسم لأول مرة بعد إعداد المفتاح. راجع حدود الاستخدام والفوترة في Google Cloud، واضبط حصة للمشروع للحد من الاستهلاك.

## لوحة الإدارة
- المدير يفتح `/admin` بعد تسجيل الدخول. يمكنه إضافة أعضاء، تفعيلهم أو إيقافهم، تعيين دور المدير، وتعيين كلمة مرور جديدة.
- يمكنه إضافة الأقسام وتعديل عنوانها ووحدتها ومسؤولها وحالتها وصلاحية تحريرها، وأرشفتها واستعادتها. الأرشفة تحفظ المحتوى والتعليقات.
- يمكنه تغيير ألوان الواجهة الفاتحة والداكنة ولون التمييز. الإعدادات محفوظة في قاعدة البيانات.
- الأرشفة لا تنتهي تلقائيًا ولا تحذف البيانات. يستطيع المدير استعادة القسم أو حذفه نهائيًا من الأرشيف؛ الحذف النهائي يزيل القسم وتعليقاته بعد تأكيد المتصفح.
- تتم ترقية `ADMIN_USERNAME` إلى مدير عند كل تشغيل. استخدم اسم مستخدم موجودًا في قاعدة البيانات، أو أضف الاسم في `.env` قبل التشغيل.

## الاتصال الضعيف والعمل دون اتصال
- تبقى الصفحة المفتوحة ظاهرة عند انقطاع الإنترنت، وتُحفظ مسودة القسم محليًا في المتصفح.
- إذا ضغطت «حفظ التغييرات» أثناء الانقطاع، تُرسل المسودة تلقائيًا عند عودة الاتصال. معرّف طلب التعليق يمنع إنشاء تعليق مكرر عند إعادة المحاولة.
- تُخزَّن ملفات الواجهة وشاشة Offline فقط. محتوى الأقسام لا يُخزَّن في Service Worker؛ يلزم الاتصال لفتح الأقسام أو مزامنة التغييرات. عند إعادة فتح الموقع بلا اتصال تظهر شاشة توضح ذلك.

## القواعد
- الكل يشوف كل الأقسام ويعلّق عليها.
- التعديل: لمسؤول القسم فقط؛ وهو يقدر يفتحه «للفريق كله» أو لـ«شخص محدد».
- أقسام الوحدة 4 بلا مسؤول: أي عضو يعدّلها.
- لتعديل الأقسام أو المسؤولين: عدّل مصفوفة `S` داخل `seed()` في server.js قبل أول تشغيل (أو احذف مجلد data وأعد التشغيل).

## النشر المجاني 24/7 (Neon + Render)
1. **Neon**: أنشئ مشروعاً، وانسخ رابط الاتصال (Connection string) — يحوي `sslmode=require`.
2. ارفع المشروع إلى GitHub (المستودع الخاص يكفي). لا ترفع `data/` ولا `.env` (موجودان في `.gitignore`).
3. **Render** → New → Web Service → اختر المستودع:
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Environment: `DATABASE_URL` (رابط Neon)، `COOKIE_SECURE=1`، `TRUST_PROXY=1`، `LOG_INITIAL_PASSWORDS=1` (لمرة واحدة فقط إذا بدأت بقاعدة فارغة)
4. لنقل بياناتك الحالية شغّل سكربت النقل من جهازك قبل أول تسجيل دخول (الخطوة أعلاه) بنفس `DATABASE_URL`.
5. Render المجاني ينام بعد 15 دقيقة بلا زيارات (الفتح التالي يأخذ حوالي دقيقة). لإبقائه مستيقظاً استخدم خدمة ping خارجية تزور رابط الموقع كل 5 دقائق.

## هيكل الكود
```
server.js            نقطة التشغيل (تشغيل السيرفر، تنظيف الجلسات، الإغلاق الآمن)
src/config.js        متغيرات البيئة و .env
src/db.js            الاتصال بـ PostgreSQL والجداول والفهارس
src/seed.js          البيانات الأولية والاعتماديات الأولية
src/i18n.js          النصوص العربية/الإنجليزية
src/permissions.js   صلاحيات التعديل والإدارة
src/auth.js          الجلسات وCSRF
src/repo.js          استعلامات مشتركة (المستخدمون، الإعدادات، الاعتماديات)
src/views.js         قطع HTML المشتركة
src/flow.js          حساب مراحل الاعتماديات
src/translate.js     الترجمة
src/routes/*.js      المسارات: auth, admin, dashboard, flow, sections
scripts/             سكربت نقل بيانات SQLite
test/                الاختبارات
```
لإضافة صفحة جديدة: أنشئ ملفاً في `src/routes/` يصدّر `express.Router()` وأضف اسمه في القائمة داخل `src/app.js`.

## ملاحظات السعة
- الفهارس مضافة على الأقسام والتعليقات والاعتماديات والجلسات.
- تشفير كلمات السر async فلا يعطّل السيرفر. الإعدادات (الألوان) تُخزَّن مؤقتاً 10 ثوانٍ.
- الجلسات المنتهية تُحذف كل ساعة.
- خلف بروكسي (Render) فعّل `TRUST_PROXY=1` ليعمل حدّ محاولات الدخول حسب IP الزائر الحقيقي.
- حدّ محاولات الدخول يعمل داخل ذاكرة نسخة واحدة؛ لو شغّلت أكثر من نسخة من السيرفر انقله إلى جدول في القاعدة.
- لم يُنفَّذ بعد: ترقيم صفحات التعليقات (يحتاج تعديل واجهة).

## بنية الكود
- `server.js` نقطة التشغيل فقط. المنطق في `src/`: `config` (البيئة)، `db` (الاتصال والجداول والفهارس)، `seed` (البيانات الأولية)، `i18n`، `views` (القالب العام)، `auth`، `permissions`، `flow` (حساب المراحل)، `repo` (استعلامات مشتركة)، `translate`.
- المسارات في `src/routes/`: `auth`، `dashboard`، `sections`، `flow`، `admin`.

## الروابط
- القسم: `/sections/:id` (حفظ: `/sections/:id/save-all`)، حذف تعليق: `/comments/:id/delete`.
- الروابط القديمة `/s/:id` و`/c/:id/delete` تُحوَّل تلقائيًا إلى الجديدة، فلا تنكسر الإشارات المرجعية.
- التعليقات: تظهر آخر 30 تعليقًا في الصفحة، و`?comments=all` يعرضها كلها.

## الفرق والمشاريع
- الهيكل: فريق ← مشاريع ← أقسام. العضو يرى مشاريع الفرق التي ينتمي إليها فقط، والمدير يرى الكل.
- يظهر مبدّل المشاريع في اللوحة و`/flow` عندما يرى العضو أكثر من مشروع.
- من `/admin`: إنشاء فريق، تحديد أعضائه، إنشاء مشروع لفريق، وإضافة قسم إلى مشروع. مسؤول القسم ومن يُسمح له بالتعديل يجب أن يكونوا من فريق المشروع.
- البيانات الموجودة (أو الزرع الأولي) تُنسب تلقائيًا إلى فريق ومشروع افتراضيين باسم TENDRO عند أول تشغيل، فلا يضيع شيء بعد النقل من SQLite.
- قائمة الأعضاء تُخزَّن مؤقتًا 10 ثوانٍ وتُحدَّث فورًا عند إضافة عضو أو تعديله.

## الإشعارات
- جرس في الهيدر بعدّاد غير المقروء (يتحدّث كل دقيقة)، وصفحة `/notifications` فيها «تحديد الكل كمقروء».
- يصل إشعار لكل أعضاء فريق المشروع (عدا صاحب الفعل) عند: أي تغيير في حالة المهمة (بدء العمل، جاهز للمراجعة، اكتمال، رجوع للبداية)، وإضافة ملف أو رابط.
- يصل إشعار لمسؤول القسم فقط عند حذف تعليق من قسمه.
- «تعليق جديد»: يصل لمسؤول القسم، ولمن له إذن التعديل (وضع شخص)، ولكل من علّق سابقًا على القسم، عدا كاتب التعليق، ولأعضاء فريق المشروع الفعّالين فقط.
- الصياغة محايدة جنسيًا بالعربية، وتُعرض بلغة القارئ. المقروء يُحذف بعد 30 يومًا وأي إشعار بعد 180 يومًا.

## الملفات والروابط
- في صفحة القسم: رفع ملف (Word, PDF, Excel, PowerPoint, صور png/jpg/gif/webp, txt) أو إضافة رابط http/https.
- الملفات تُخزَّن داخل PostgreSQL لأن Render لا يحفظ ملفات على القرص. الحد الافتراضي 5MB للملف (`MAX_FILE_MB`)، و30 مرفقًا للقسم، وسقف إجمالي 600MB (`MAX_TOTAL_MB`). خطة Neon المجانية 1GB فقط، فراقب المساحة.
- النوع يُحدَّد بالخادم: الامتداد يجب أن يكون مسموحًا ومحتوى الملف يطابقه (ملف exe بامتداد pdf يُرفض). التنزيل لأعضاء المشروع فقط، بترويسات `nosniff` و`sandbox`.
- يحذف المرفق من رفعه أو مسؤول القسم أو المدير. الصور تظهر مصغّرة وتُفتح مباشرة، وغيرها يُنزَّل.

## الأمان
- كلمة المرور الجديدة 8 أحرف على الأقل. تغييرها أو إعادة تعيينها من المدير أو إيقاف العضو يُنهي جلساته الأخرى.
- ترويسات: CSP صارمة، HSTS (مع `COOKIE_SECURE=1`)، Permissions-Policy، COOP/CORP، X-Frame-Options. رمز CSRF يُقارن بزمن ثابت. تحديد 120 طلب كتابة في الدقيقة لكل مستخدم.
- رابط العودة بعد تبديل اللغة يقبل مسارًا داخليًا فقط (إغلاق إعادة التوجيه المفتوحة). الأخطاء تُعرض صفحة عامة دون تفاصيل.
- حدود معروفة: تحديد محاولات الدخول في الذاكرة (يحتاج `TRUST_PROXY=1` على Render)، قائمة الأسماء ظاهرة في صفحة الدخول بالتصميم، ملفات Office قد تحمل وحدات ماكرو فلا تفتحها إلا من مصدر موثوق، ولا تترك `LOG_INITIAL_PASSWORDS=1` مفعّلًا.
